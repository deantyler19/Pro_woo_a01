# 백엔드 / 서버 개발 스킬

앱이 안정적으로 데이터를 주고받고 보관하는 뼈대를 만든다. 보안과 데이터
무결성을 최우선으로, 확장 가능하고 관측 가능한 서비스를 설계한다.

> 사진 앱 원칙: 사진 분석은 **온디바이스**가 기본. 서버는 계정·구독·설정 동기화·
> 익명 통계 등 **메타데이터**만 다루고, 원본 사진은 서버에 올리지 않는다(선택적
> 백업 기능을 넣는다면 종단간 암호화 + 명시적 동의 필수).

## API 설계 원칙
- 리소스 중심 URL, 동사는 HTTP 메서드로(`GET/POST/PATCH/DELETE`).
- 일관된 응답 봉투 + 표준 에러 형식:
```json
{ "error": { "code": "INVALID_TOKEN", "message": "...", "requestId": "..." } }
```
- 페이지네이션(cursor 권장), 필터·정렬 쿼리 규약 통일.
- 버저닝(`/v1`), 하위호환 유지, 파괴적 변경은 새 버전.
- 멱등성(idempotency-key)으로 재시도 안전성 확보(특히 결제·쓰기).

## 인증 / 인가
- 모바일 1순위: **Sign in with Apple**(iOS 필수 심사 요건일 수 있음) + OAuth2.
- 토큰: 짧은 수명 **Access(JWT)** + 회전형 **Refresh**. Refresh 재사용 탐지.
- 비밀번호는 **Argon2id/bcrypt** 해시(평문·MD/SHA 단독 금지).
- 인가는 서버에서 항상 재검증(클라이언트 신뢰 금지), RBAC/스코프.
- 민감 토큰은 iOS Keychain 저장(클라이언트 측 가이드).

## 데이터 모델링
- 명확한 제약(NOT NULL·FK·UNIQUE), 마이그레이션은 버전관리·롤백 가능.
- 인덱스는 쿼리 패턴 기반으로(읽기 경로 프로파일링 후).
- 개인정보 최소 수집, 삭제권(계정·데이터 완전 삭제) 흐름 설계(GDPR/앱스토어).
- 소프트 삭제 vs 하드 삭제 정책 명시.

## 결제 / 구독
- iOS는 **StoreKit 2 인앱결제**가 기본. 서버는 **App Store Server Notifications v2**로
  구독 상태 동기화 + 영수증(JWS) 검증.
- 가격·플랜은 서버 설정화, 환불·유예기간·갱신 상태 머신으로 관리.
- 결제 쓰기는 멱등 처리, 웹훅은 서명 검증 + 재시도 수용.

## 보안 체크리스트
- [ ] 전 구간 HTTPS/TLS, HSTS.
- [ ] 입력 검증·출력 인코딩(SQLi/XSS 방지), ORM 파라미터 바인딩.
- [ ] 레이트 리미팅·브루트포스 방지, 계정 잠금.
- [ ] 시크릿은 환경변수/시크릿 매니저(코드·리포 커밋 금지).
- [ ] 최소 권한 원칙, 의존성 취약점 스캔(SCA).
- [ ] PII 로그 마스킹, 감사 로그.

## 신뢰성 / 관측성
- 구조화 로깅(requestId 상관관계), 메트릭(RED: Rate/Errors/Duration), 분산 트레이싱.
- 헬스체크·그레이스풀 셧다운, 타임아웃·서킷브레이커·재시도(지수 백오프).
- 마이그레이션·배포는 무중단(blue-green/rolling), 롤백 계획.

## 기술 스택 선택(예시)
- Node.js(NestJS) / Python(FastAPI) / Kotlin(Spring) / Go — 팀 역량 기준.
- DB: PostgreSQL(관계형 기본) + Redis(캐시·레이트리밋). 객체스토리지는 S3 호환.
- 스택 결정·인프라 비용·외부 서비스 연동은 사용자 승인 후 진행.

## 산출물 형식
- OpenAPI(스웨거) 스펙 + 엔드포인트 표(메서드·경로·인증·요청/응답·에러코드).
- ERD(엔터티·관계·인덱스) + 마이그레이션 파일.
- 시퀀스 다이어그램(인증·결제 등 핵심 플로우).

## 원칙
- 보안·프라이버시는 사후가 아니라 설계 단계에서 내장한다.
- 외부로 데이터를 보내는 모든 결정은 사용자에게 명확히 고지·승인받는다.
- "동작함"이 아니라 "장애·악용 상황에서도 안전함"을 기준으로 본다.
